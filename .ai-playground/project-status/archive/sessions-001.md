#### 2026-09-04 (session 2, shlomi) - Silicon Labs driver test and online investigation
- **Completed:** Installed and approved the official Silicon Labs CP210x VCP macOS driver v6.0.3. Confirmed `com.silabs.cp210x` is activated and enabled; adapter appeared as both `/dev/cu.SLAB_USBtoUART` and `/dev/cu.usbserial-0001`. Retested both device nodes and researched Makerfabs GitHub, documentation, issues, Silicon Labs documentation, and relevant maker forum reports.
- **Key findings:**
  - Every requested baud (9600, 115200, 921600) delivered roughly 523-526 KB/s on both device nodes, with zero valid 81-byte `0x2A ... 0x23` frames and only seven byte values (`00/0c/70/7c/80/f0/fc`).
  - At 115200, the received data is an exact 63-byte pattern repeated indefinitely. A real 115200 8N1 UART can carry only about 11,520 B/s, so this stream cannot originate from the anchor UART. The 63-byte periodicity strongly suggests USB receive-packet/buffer replay.
  - The original built-in macOS path had already ignored baud settings at about 84,150 B/s. The Silicon Labs DriverKit driver made the symptom worse (~525 KB/s replay), so the third-party driver is not the original cause but may exacerbate it.
  - Makerfabs officially specifies TTL UART at 115200 and a generic USB-TTL adapter; CP2102 is not required. The GitHub Assistant is Windows-only. The only current Gen2 GitHub issue is unrelated parser logic; no Makerfabs/MakerHub community post documents this exact failure.
  - Forum reports only provide anecdotal support that cheap CP2102 adapters can be defective or unreliable; they do not establish the cause for this unit.
- **Context:** The driver installer initially failed Gatekeeper because the DMG inherited a WhatsApp/App Sandbox quarantine marker, then appeared to hang while waiting for Driver Extensions approval. After approval the extension activated normally.
- **Decision:** Test the same CP2102 + anchor wiring on Windows. If Windows also ignores baud or repeats/corrupts data, replace the adapter with a known-good FTDI, CH340, or genuine CP2102N. If Windows works, treat this as a macOS driver compatibility problem.

#### 2026-10-04 (reference notes) - Extended Context Ported From status.md
- **Makerfabs support reply (email dated 2026-09-07, processed 2026-09-13, commit 81d417b):** "The AOA2AN need to be set with CH340 before usage, while the AOA2TA do no need". The AOA2TA is a chipset; Makerfabs does not sell a separate board for it. The "AOA Tag PCBA with small battery" (robot kit) is for button/feedback only, not positioning. CH340 likely explains both the zero-byte serial reads (unconfigured anchor may not stream) and the Assistant's empty port dropdown (may enumerate only CH340 ports). The Gen2 repo ships `Driver/CH341SER.EXE`, also pointing to CH340.
- **Our tag (photo 2026-09-13):** bare castellated SMD module, label `JL-U2-CA`, Sn 100543, component marked 8060 (onboard ceramic antenna), u.FL/IPEX connector (optional external antenna), anchor/tag (Chinese: 基站/标签) checkboxes on the label.
- **Tag power:** 3.3V/200mA rated, ~12mA operating. Do NOT feed it from a CH340 3.3V pin (~25mA limit). Use the ESP32 dev board 3.3V pin or an AMS1117-3.3 regulator board.
- **Anchor board:** MaUWB_AOA Gen2 Anchor, STM32F103 + DW3000, UART-TTL at 115200, 5V supply. Pins: TXD(1), RXD(3), GND(4), VCC(5). Front UART connector `VCC, GND, RXD, TXD` = red, black, yellow, green. Back-side `VCC / CLK / DIO / GND` is a debug/programming interface, not UART.
- **Tag pins (Gen2 Tag datasheet v1.0):** pin 1 GND; pin 16 VCC 3.3V; pin 11 UART_TX, pin 12 UART_RX at 115200; pin 13 reset (active low); pin 5 green status LED (flashes when powered); pin 6 red power LED (solid when on); pins 3/4 download CLK/DIO; pins 2,7,8,9,10,14,15 NC (leave floating). CH9 band 8987.2 MHz; tag continuously emits UWB, anchor computes distance+angle.
- **Positioning frame (binary, 81 bytes):** head 0x2A (0), cmd_len uint16 (1), cmd_saddr uint64 (3), cmd_daddr uint64 (11), cmd_type uint8 (19; 1=positioning, 0x64=positioning+RSSI, which is an 89-byte frame), cmd_direct uint8 (20), tag_time uint32 (21), anc_addr16 uint16 (25), tag_addr16 uint16 (27), tag_sn uint8 (29), tag_mask uint8 (30); per-anchor filter_angle int16 (deg) + filter_range uint16 (cm) for anchors 0-3 at 31-46; tag_detail_para uint32 (47, battery/charging bits); accel x/y/z uint16 (51/53/55); gyro x/y/z uint16 (57/59/61); self_raw_angle int16 (63); self_raw_range uint16 (65); self_raw_degree int32 (67); angle_360 uint16 (71); angle_dir uint8 (73); reserve 5B (74); checksum uint8 XOR over cmd_saddr..reserve (79); foot 0x23 (80). Little-endian (datasheet example: F9 FF = -6 deg, 60 00 = 96 cm). The anchor streams these on power-up per datasheet.
- **Datasheet sources:** https://github.com/Makerfabs/MaUWB_AOA-Gen2 -> datasheet/Anchor and datasheet/Tag (.docx); tag firmware bins in `datasheet/Tag/bin/`. Local copies in `docs/`.
